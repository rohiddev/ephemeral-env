 The cleanest bank-regulation-friendly approach that fits your setup:

  IDP workflow page 1
    → hoover-service generates a short-lived token (e.g. 2hr expiry)
    → link shown to user includes token:
      https://upload.internal.bank.com/nexus-upload?token=NX-20260429-a3f9

  Upload page loads
    → validates token with hoover-service (is it real, is it expired?)
    → if invalid/expired → page shows error, no upload allowed
    → if valid → file picker shown

  User uploads file
    → token tied to upload reference in hoover-service
    → token marked used — cannot upload again with same token

  User returns to IDP workflow
    → pastes upload reference NX-20260429-a3f9
    → pipeline validates reference exists in hoover-service before proceeding

  This gives you:
  - Only IDP workflow users can get a token
  - Token expires (audit + regulation)
  - Single-use — no replay
  - No username/password on the page
  - Full audit trail: token → user → artifact → pipeline run

Good picture. Here's the full design:

  ---
  Architecture

  IDP Workflow Page 1
    → "Generate Upload Link" button (ValidateAndFetch)
    → calls POST /mock-api/nexus/token/generate
    → shows link: https://openshift-host/nexus-upload?token=NX-20260429-a3f9
    → user clicks link, opens upload page in new tab

  Upload Page (served by same hoover-service Go binary)
    → reads ?token from URL
    → calls GET /mock-api/nexus/token/validate
    → shows file picker + progress bar
    → chunked POST /mock-api/nexus/file/upload
    → shows: Upload Reference: NX-20260429-a3f9  [Copy]

  User returns to IDP workflow
    → pastes upload reference into new field
    → fills artifact details → submits

  Pipeline
    → Stage 1: validate uploadReference exists (GET /file/verify)
    → Stage 2: skipped — file already in S3
    → Stage 3+: scan → approval → Nexus upload (unchanged)

  Token security

  - Token: NX-YYYYMMDD-xxxxxxxx — generated by hoover-service
  - 2hr expiry stored in memory
  - Single-use — marked used after file upload completes
  - Upload page rejects expired/used/invalid tokens
  - Pipeline verifies uploadReference before proceeding — if not found, pipeline fails
