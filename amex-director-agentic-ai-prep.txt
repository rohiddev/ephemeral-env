PART 3 — THE GAPS TO CLOSE BEFORE THE INTERVIEW
---

GAP 1: LANGCHAIN / LANGGRAPH / LLAMAINDEX FLUENCY
  Amex explicitly lists these. You use Google ADK.
  You do not need to have built with LangChain — but you must be able to
  speak intelligently about when you would choose it vs ADK vs building
  lighter primitives. Prepare a clear comparison.

  Study: LangGraph's node/edge/state model, how it handles cycles,
  how it differs from ADK's sub-agent delegation pattern.
  Know: LangChain's tool_calling abstraction, memory types (buffer,
  summary, entity), retriever interface.
  Know: LlamaIndex's QueryEngine, RAG pipeline, document ingestion.

  Your answer when asked: "I built production multi-agent systems using
  Google ADK with Bedrock on AWS. ADK gave me code-first agent construction,
  structured tool calling, and session management. LangGraph is closer to
  a graph-based state machine approach — better for cyclical workflows with
  explicit state transitions. I would choose LangGraph when the agent
  loop has well-defined states and explicit transition conditions.
  I would choose ADK when the hierarchy of agents and tool calling
  needs to be code-first and testable. I would build lighter primitives
  when the framework's abstractions add more complexity than they remove —
  which is often the case for simple RAG or single-model pipelines."

GAP 2: KAFKA AND EVENT-DRIVEN AGENTIC PATTERNS
  Amex lists Kafka explicitly. Know how Kafka fits into agentic systems.

  Key concept: agents as consumers of event streams.
  An agent workflow triggered by a Kafka event (new loan application,
  fraud alert, customer complaint) rather than an HTTP call.
  Event sourcing: agent decisions published as events for audit and replay.
  Exactly-once semantics: idempotent agent actions keyed on event offset.

  Prepare to explain: "How would you design a fraud detection agent
  that processes real-time transaction events?" Answer includes:
  Kafka consumer group -> trigger agent invocation per event ->
  agent calls tools (lookup account, check pattern, assess risk) ->
  agent decision published back to a Kafka topic -> downstream system acts.
  Temporal handles the durable execution of multi-step agent logic per event.

GAP 3: PYTORCH AND HUGGING FACE ECOSYSTEM
  The JD mentions PyTorch, Hugging Face, fine-tuning, embeddings,
  inference tooling. You may not have deep hands-on here.

  Prepare the conceptual level:
  - Embeddings: know sentence-transformers (all-MiniLM, BGE, E5).
    Know why embedding model choice affects RAG quality.
    Know the difference between retrieval-optimized and semantic-optimized models.
  - Fine-tuning: know LoRA/QLoRA (efficient fine-tuning of large models
    by training low-rank adapter matrices, not full weights).
    Know when to fine-tune vs RAG vs prompt engineering.
    Fine-tune when: domain terminology is highly specific, the model
    consistently fails at a task type, you have labeled training data.
    RAG when: knowledge is dynamic, facts change frequently.
  - Inference: know vLLM (high-throughput inference server, PagedAttention),
    llama.cpp (CPU inference), ONNX (model portability).
    Know Bedrock's managed inference vs self-hosted on EKS.
  - You do not need hands-on PyTorch. You need to discuss tradeoffs
    at the architectural level: managed vs self-hosted inference,
    when to fine-tune, how embedding quality affects RAG.

GAP 4: EVALUATION FRAMEWORKS FOR AGENTIC SYSTEMS
  The JD specifically mentions "evaluation tooling for autonomous systems."
  This is a real gap in most agentic AI work and a differentiator if you
  know it well.

  Prepare:
  - Agent evaluation is harder than model evaluation because the
    full trajectory matters (did the agent take the right steps?),
    not just the final answer.
  - Metrics: task success rate, tool call accuracy, step efficiency
    (did it use too many tool calls?), hallucination rate on cited facts,
    grounding rate (did every claim come from a retrieved document?),
    latency per request, cost per request (token usage).
  - Frameworks: LangSmith (LangChain's eval and tracing platform),
    Weights & Biases (experiment tracking + eval), Ragas (RAG-specific
    evaluation: faithfulness, answer relevance, context precision),
    custom eval harnesses (run a golden question set, check answers
    against expected responses or rubrics, CI/CD integration).
  - Amex-specific: in a regulated environment, evaluation is also
    compliance evaluation. Does the agent cite approved sources?
    Does it escalate when it should? Does it never fabricate regulatory facts?
    Safety evaluation = does the agent stay within its autonomy boundary?

GAP 5: FINTECH-SPECIFIC AGENTIC CONSIDERATIONS
  Amex is a financial services company. Know what makes agentic AI
  different in fintech vs a general enterprise.

  Key concerns:
  - Explainability: regulators (OCC, CFPB, FINRA) may require that
    any AI-driven decision affecting a customer be explainable.
    An agent that denies a credit limit increase must be able to say why.
    RAG with citations is one approach. Structured reasoning traces are another.
  - Auditability: every agent action that touches a customer account
    must be immutably logged. Who initiated it, what data was accessed,
    what decision was made, what happened next.
  - Model risk management (MRM): banks and card networks must validate
    AI models before deploying them to production. This includes
    bias testing, performance benchmarking, and periodic revalidation.
    Know what an MRM process looks like at a high level.
  - PCI DSS: cardholder data must be protected. Agents must never
    log, transmit, or process raw card numbers or CVVs.
    Tokenization at ingestion. Data residency controls.
  - Fair lending: any agent that influences credit decisions must not
    discriminate on protected characteristics. Bias testing is mandatory.
  - Human override: any customer-facing agent decision of consequence
    (account action, credit decision, fraud flag) must have a human
    override path. Agents recommend; humans (or rule engines) approve.

STAGE 3 — TECHNICAL DEEP DIVE (60-90 min, often with Principal/Staff engineers)
  Goal: validate that your technical claims are real.
  Likely format: system design question + architecture review.

  System design question you should be ready for:
  "Design an agentic AI system for American Express customer service
  that handles card dispute resolution end-to-end."

  Your answer structure:
    Requirements:
      Functional: customer submits dispute, agent gathers evidence,
      agent assesses validity, agent takes action (provisional credit,
      merchant contact, case escalation).
      Non-functional: FINRA/OCC auditability, PCI DSS (no raw card data),
      99.9% availability, <3s response for interactive turns,
      human override at every material decision.

    Architecture layers:
      1. Entry: API Gateway + OAuth2/OIDC (Amex SSO). Customer authenticated.
         Dispute request hits FastAPI service.
      2. Supervisor Agent (Claude Opus via Bedrock):
         PHI/PCI redaction at entry. Classify dispute type.
         Dispatch specialist agents in parallel.
      3. Specialist agents:
         - EvidenceAgent: pull transaction records, merchant data, prior disputes
           from internal APIs (not from the LLM's memory)
         - PolicyAgent: retrieve dispute policy from Bedrock KB (RAG, cited)
         - FraudSignalAgent: query fraud scoring system, pattern history
         - CustomerHistoryAgent: account standing, dispute history, card tier
      4. Result aggregation: structured JSON with evidence, policy reference,
         recommendation (valid/invalid/escalate), confidence score.
      5. Human review gate: if confidence < threshold OR dispute amount > $X:
         Temporal workflow pauses, routes to human reviewer.
         Human reviews agent evidence pack, approves or overrides.
         Temporal signal resumes workflow.
      6. Action: provisional credit issued, merchant notified,
         case logged in CRM with full agent reasoning trace.
      7. Audit: every agent step, tool call, data access logged to
         immutable CloudWatch log group with CloudTrail for AWS API calls.
         Retention: 7 years (regulatory requirement).

    Tradeoffs to raise yourself:
      - Why RAG over fine-tuning for policy? Policy changes frequently.
        RAG retrieves the current version. Fine-tuning bakes in old policy.
      - Why human gate at confidence threshold? Regulators require explainability
        for material decisions. A human in the loop satisfies that.
      - Why Temporal for the workflow? The dispute process can take days
        (waiting for merchant response). Temporal's durable timers + signals
        handle this natively without a polling loop or custom state DB.
      - Why parallel specialist dispatch? Evidence, policy, fraud, history
        are independent lookups. Sequential adds latency; parallel is ~1s.
      - Why structured output from each agent? Aggregation must be
        deterministic. An LLM-based merge adds hallucination risk.
        Structured JSON + deterministic Python aggregation is auditable.

  Architecture review:
  They may show you a design and ask you to critique it.
  Common issues to spot:
    - Missing timeout on any downstream call
    - No circuit breaker on external API (fraud scoring, merchant network)
    - Agent has access to raw card data (PCI violation)
    - No audit trail for agent decisions
    - Agent makes final decision without human gate on high-value disputes
    - No retry policy on tool calls
    - Session state stored in memory only (not durable)
    - No evaluation framework — how do you know the agent is right?

    PHI redaction at entry. Guardrails at the tool boundary.

PART 9 — RAPID-FIRE TECHNICAL DEFINITIONS TO HAVE CLEAN
---

Know these cold. You may be asked any of them in passing.

  Autonomy boundary       The line between what an agent decides alone
                          and what requires human approval. Defined by
                          risk level, regulatory requirement, and confidence
                          threshold. Not a technical decision — a business
                          and compliance decision enforced technically.

  Grounding               Anchoring an LLM response in retrieved documents.
                          Every claim has a source. Prevents hallucination.
                          Measured by faithfulness (does the answer match
                          the source?) and context precision (was the
                          right document retrieved?).

  RAG vs fine-tuning      RAG: dynamic knowledge retrieval at query time.
                          Good for: changing knowledge, large document sets,
                          citation requirements.
                          Fine-tuning: baking knowledge into model weights.
                          Good for: stable domain-specific tasks, style
                          adaptation, task-specific performance gains.
                          In regulated environments: RAG is usually preferred
                          because the knowledge source is auditable.

  Tool use / function calling  The mechanism by which an LLM calls external
                          functions. The model outputs a structured call
                          (name + arguments). Your code executes it.
                          The result goes back into the model's context.
                          This is how agents take actions beyond generating text.

  Memory types            In-context: everything in the current prompt window.
                          External/semantic: vector store of past interactions.
                          Episodic: structured history of past agent runs.
                          Procedural: learned patterns encoded in model weights
                          (fine-tuning) or system prompt.

  Model gateway           A proxy layer in front of LLM APIs.
                          Handles: routing, rate limiting, key management,
                          cost metering, fallback between providers,
                          content filtering. LiteLLM Proxy is an example.

  MCP                     Model Context Protocol. Anthropic standard.
                          Defines how agents discover and call tools
                          via a standard wire protocol. Decouples tool
                          providers from agent frameworks.

  Temporal / durable exec  Workflow engine that guarantees a long-running
                          process completes even across failures.
                          Workflows pause (for human approval, external event)
                          and resume exactly where they stopped.
                          Not an agent. Infrastructure for agents to run on.

  LangGraph               Agent framework using a directed graph model.
                          Nodes = agent steps. Edges = transitions.
                          State flows through the graph.
                          Good for: cyclical workflows, explicit state machines,
                          human-in-the-loop at defined graph nodes.

  RAGAS                   Evaluation framework for RAG systems.
                          Metrics: faithfulness, answer relevance,
                          context precision, context recall.
                          Run against a golden question set to measure
                          RAG pipeline quality before production.

  Semantic caching        Cache LLM responses by semantic similarity of the query.
                          If a new query is semantically close to a cached query,
                          return the cached response. No model call needed.
                          Reduces cost and latency for repeated similar questions.

  Model risk management   The bank/financial services governance process for
                          validating AI/ML models before production deployment.
                          Includes: bias testing, performance benchmarking,
                          documentation, periodic revalidation.
                          OCC SR 11-7 guidance is the regulatory reference.

  LoRA / QLoRA            Parameter-efficient fine-tuning methods.
                          Train only small adapter matrices, not the full model.
                          QLoRA adds quantization for reduced memory usage.
                          Allows fine-tuning large models on modest hardware.

  vLLM                    High-throughput LLM inference server.
                          PagedAttention: efficient KV cache management.
                          Continuous batching: maximizes GPU utilization.
                          Used for self-hosted inference at scale.

1. LangGraph (Highest Priority)
What is LangGraph?

One-line definition

LangGraph is a framework for building AI agents that can make decisions,
remember information, call tools, and repeat steps until a task is complete.

Think of it like a workflow engine for AI agents.

Important words

Know these words well.

Word	Meaning
Node	A step in the workflow
Edge	Connection between nodes
State	Shared memory used across the graph
Conditional Edge	AI decides which node to execute next
Tool	External API or function
Agent	LLM + tools + memory
Loop	Agent repeats until goal achieved
Checkpoint	Save current state
Human in the Loop	Person approves before continuing
Explain State

This is asked frequently.

Instead of each node remembering information separately,

LangGraph stores everything in one shared object called State.

Example

User:
"I forgot my credit card."

State

{
 customer_id
 card_status
 authentication_status
 fraud_score
 conversation_history
}

Every node reads and updates this.

2. RAGAS (Very Important)

RAGAS =

Retrieval Augmented Generation Assessment

Used to evaluate RAG systems.

Know these metrics.

Faithfulness

Did the answer come from retrieved documents?

Example

Document says

Interest rate = 8%

LLM says

Interest rate = 12%

Faithfulness is poor.

Answer Relevancy

Did the answer actually answer the user's question?

Context Precision

How much retrieved context was actually useful?

Higher precision

↓

Less junk

↓

Better retrieval

Context Recall

Did retrieval find ALL important documents?

Context Relevancy

Were retrieved documents relevant?

Interview definition

RAGAS evaluates retrieval quality and answer quality without requiring human labels.

Director-Level Interview Tips

At the director level, interviewers care less about coding syntax and more about architecture, leadership, and trade-offs. Be prepared to answer questions like:

Why did you choose a multi-agent architecture instead of a single agent?
How do you measure whether an AI agent is successful?
How would you reduce hallucinations in a production system?
How would you secure customer data in an AI workflow?
How would you monitor AI performance after deployment?
What risks concern you most when deploying AI in a financial institution?
How do you balance innovation with regulatory compliance?
Tell me about a time you influenced leaders without direct authority.

Given your experience leading internal developer platforms and building AI solutions,
you should also be ready to connect every technical decision back to business outcomes—improved
customer experience, reduced operational cost, increased developer productivity, lower risk, and
stronger governance. This is often what differentiates director-level candidates from senior engineers.
