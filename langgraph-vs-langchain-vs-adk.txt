LangChain vs LangGraph vs Google ADK
==========================================================================
What they are, how they differ, when to use each, and how they overlap
==========================================================================


---
PART 1 — ONE-LINE SUMMARY OF EACH
---

LangChain    A component library. Gives you building blocks: LLMs, prompts,
             tools, retrievers, output parsers, memory. Composable via LCEL (|).
             Think: "a toolkit of AI parts."

LangGraph    A graph orchestration framework built ON TOP of LangChain.
             Gives you control flow: nodes, edges, state, loops, branching,
             parallelism, checkpointing. Think: "a state machine for agents."

Google ADK   An opinionated agent framework by Google. Gives you a full
             agent runtime: built-in agent types, session management, tool
             protocol, evaluation harness, and deployment targets (Vertex AI,
             Agent Engine). Think: "a complete agent platform with opinions baked in."


---
PART 2 — THE ANALOGY THAT MAKES IT CLICK
---

Think of building a house:

LangChain    = the raw materials and tools (bricks, cement, hammer, saw).
              You can build anything but you assemble everything yourself.

LangGraph    = the architectural blueprint + scaffolding system.
              You still use LangChain's materials but LangGraph tells you
              how rooms connect, where doors go, how to wire the electrical.

Google ADK   = a prefab house kit with a set floor plan.
              Most rooms are already laid out for you. Faster to move in.
              Harder to knock down a wall and redesign from scratch.

You can use LangChain without LangGraph (just LCEL chains, no graph).
You cannot use LangGraph without LangChain (it imports from langchain-core).
You can use ADK standalone (it does not depend on LangChain or LangGraph).


---
PART 3 — WHAT EACH ONE ACTUALLY DOES
---

LANGCHAIN — WHAT IT GIVES YOU

   ChatModel interface
     Uniform API across all LLM providers.
     ChatBedrockConverse, ChatOpenAI, ChatAnthropic, ChatVertexAI all
     implement the same .invoke() / .stream() / .batch() methods.
     Swap providers without changing business logic.

   LCEL (LangChain Expression Language)
     Chain components with | operator:
       prompt | llm | parser
     Every component is a Runnable: .invoke(), .stream(), .batch(), .ainvoke()
     Parallel execution: RunnableParallel({a: chain_a, b: chain_b})

   Prompt Templates
     ChatPromptTemplate, MessagesPlaceholder, {variable} interpolation.

   @tool decorator
     Turns a Python function into a tool with name, description, schema.
     The LLM reads the description to decide when to call it.

   Output Parsers
     StrOutputParser, JsonOutputParser, PydanticOutputParser.

   Retrievers
     Anything with .invoke(query) -> list[Document].
     Vector stores, Bedrock Knowledge Bases, web search.

   Memory / Chat History
     ChatMessageHistory, RunnableWithMessageHistory.

   Document Loaders, Text Splitters, Embeddings
     Load PDFs, Word docs, web pages. Chunk them. Embed them.
     Foundation for RAG pipelines.

   What LangChain does NOT give you:
     - Looping (no agent loop, just chains)
     - Branching based on state
     - Parallel agent dispatch
     - Persistent state across invocations (no checkpointing)
     - Human-in-the-loop pausing
     AgentExecutor existed but was opaque and limited. LangGraph replaced it.


LANGGRAPH — WHAT IT GIVES YOU (on top of LangChain)

   StateGraph
     Define nodes (Python functions) and edges (control flow) explicitly.
     Every agent behavior is a visible, testable graph node.

   State (TypedDict)
     Shared data bag. All nodes read from and write to it.
     Reducer (Annotated[list, operator.add]): appends instead of replaces.
     Critical for parallel agents writing to the same field safely.

   Conditional Edges
     Route to different nodes based on state at runtime.
     Router function: state -> node_name (or list of Send() for parallel).

   Send() — Parallel Dispatch
     Return [Send("node_a", state), Send("node_b", state)] from a router.
     Both nodes run simultaneously. Results accumulate via reducer.
     This is how fan-out / fan-in multi-agent supervisors work.

   Checkpointing
     MemorySaver, SqliteSaver, PostgreSQL.
     State saved after every node. Resume from any point.
     thread_id = session identity. Same thread = shared memory.

   Human-in-the-Loop
     interrupt() pauses the graph. Human inspects/modifies state. Resume.

   Time Travel
     Replay from any past checkpoint. Debug agent decisions historically.

   Streaming
     graph.stream() yields state updates node by node.
     stream(mode="messages") yields LLM tokens as they generate.

   Subgraphs
     A compiled graph as a node inside another graph.
     Specialist agents as subgraphs inside a supervisor graph.

   Built-in Prebuilt Nodes
     ToolNode: executes tool_calls from AIMessage.
     tools_condition: routes to "tools" or END based on tool_calls presence.

   What LangGraph does NOT give you (that ADK does):
     - A built-in agent runner / CLI (you invoke() yourself)
     - Opinionated agent types (LLM agent, sequential agent, loop agent)
     - Built-in evaluation harness
     - Native Vertex AI / Agent Engine deployment
     - Built-in A2A (Agent-to-Agent) protocol support


GOOGLE ADK — WHAT IT GIVES YOU

   Opinionated Agent Types (out of the box)
     LlmAgent: the standard ReAct agent. Give it a model + tools + system prompt.
     SequentialAgent: runs sub-agents in order, passing context forward.
     ParallelAgent: runs sub-agents simultaneously, merges results.
     LoopAgent: repeats a sub-agent until a stopping condition.
     You don't define the loop yourself — ADK runs it for you.

   Model-Agnostic via LiteLLM
     ADK uses LiteLLM as a translation layer.
     Point at Gemini, Claude (Bedrock), GPT-4, any OpenAI-compatible endpoint.
     model="bedrock/anthropic.claude-sonnet-4-5" just works.

   Built-in Session Management
     InMemorySessionService (dev), VertexAI SessionService (prod).
     Sessions carry: conversation history, tool results, agent state.
     session.user_id + session.session_id = identity.

   Artifact / File Handling
     InMemoryArtifactService for passing files between agents.
     First-class concept in ADK; you'd build this yourself in LangGraph.

   Built-in Runner
     Runner wraps an agent and handles the full invocation lifecycle:
     session loading, event streaming, response assembly.
     You call runner.run_async(user_id, session_id, message).

   Event Streaming
     ADK yields events (LlmRequest, LlmResponse, ToolCall, ToolResponse)
     as the agent runs. First-class streaming model.

   Evaluation Harness (adk eval)
     Built-in CLI for running evaluation datasets against your agents.
     Score on tool_trajectory (did it call the right tools in order?)
     and response_match (did the final answer match expected?).
     LangGraph has no equivalent out of the box; you use LangSmith.

   A2A Protocol
     Google's Agent-to-Agent protocol. Agents expose HTTP endpoints.
     Other agents discover and call them via a standard protocol.
     LangGraph does not have A2A natively (you'd build it yourself).

   MCP Support
     Model Context Protocol for standardized tool serving.
     ADK agents can consume MCP servers as tool sources.

   Native Vertex AI / Agent Engine Deployment
     adk deploy to push your agent to Vertex AI Agent Engine.
     Managed runtime, auto-scaling, logging, monitoring.
     LangGraph equivalent: LangGraph Platform (hosted) or self-hosted server.

   What ADK does NOT give you (that LangGraph does):
     - Explicit graph definition (you see the agent type, not the loop internals)
     - Fine-grained conditional edges (ADK's routing is within LlmAgent)
     - Parallel fan-out via Send() with custom aggregation logic
     - Time travel (replay from past checkpoint)
     - Human-in-the-loop interrupt/resume pattern
     - Full state visibility and manipulation mid-graph

PART 4 — SIDE-BY-SIDE COMPARISON TABLE
---

   Dimension                LangChain         LangGraph              Google ADK
   ─────────────────────    ──────────────    ─────────────────────  ──────────────────────
   Category                 Component lib     Graph orchestration     Agent platform
   Abstraction level        Low               Medium                  High
   LLM interface            Yes (core)        Via LangChain           Via LiteLLM
   Agent loop               No (AgentExec     Yes (explicit graph)    Yes (built-in runner)
                            deprecated)
   Control flow             LCEL pipe (|)     Nodes + edges           Agent type + sub-agents
   State management         No                TypedDict + reducers    Session object
   Persistence              No                Checkpointer            SessionService
   Parallel agents          RunnableParallel  Send() + reducer        ParallelAgent
   Human-in-the-loop        No                interrupt() / resume    No (workaround)
   Time travel              No                Yes (checkpoint replay) No
   Evaluation               LangSmith         LangSmith               adk eval (built-in)
   Observability            LangSmith         LangSmith               Cloud Logging + Trace
   A2A protocol             No                No (DIY)                Yes (built-in)
   MCP support              Via community     Via community           Yes (built-in)
   Deployment target        DIY               LangGraph Platform /    Vertex AI Agent Engine
                                              self-hosted
   Cloud affinity           Provider-agnostic AWS / Azure / any       GCP / Vertex AI native
   Learning curve           Low               Medium                  Medium
   Flexibility              Very high         Very high               Medium (opinionated)
   Production tooling       Via LangSmith     Via LangSmith           Built-in (adk eval, deploy)
   Open source              Yes               Yes                     Yes (but GCP-aligned)
   Best for                 RAG chains,       Multi-agent systems,    GCP-native agents,
                            prompt eng,       complex routing,        rapid agent prototyping,
                            retrieval         enterprise agents       Vertex AI deployment

PART 5 — HOW THEY RELATE TO EACH OTHER
---

   LangChain <── used by ── LangGraph
   LangGraph uses langchain-core for: ChatModel, BaseMessage, BaseTool,
   BaseRetriever. You cannot remove LangChain from a LangGraph project.

   LangChain <── NOT used by ── ADK
   ADK has no dependency on LangChain. It uses LiteLLM for model access
   and its own tool/session abstractions.

   LangGraph <── NOT used by ── ADK
   ADK has its own orchestration. You can run ADK without LangGraph.

   Can you mix them?
   Yes. In multi_agent_aws_hc_solution_enhance, the original version used
   ADK for orchestration with Bedrock via LiteLLM. The LangGraph rewrite
   replaced ADK with LangGraph while keeping the same Bedrock backend.
   Both are valid. They solve the same orchestration problem differently.

PART 6 — THE AGENT LOOP: HOW EACH FRAMEWORK IMPLEMENTS IT
---

LANGGRAPH REACT LOOP (explicit, you define every node)

   builder = StateGraph(MessagesState)
   builder.add_node("agent", agent_fn)       # LLM reasoning
   builder.add_node("tools", ToolNode(tools)) # tool execution
   builder.add_edge(START, "agent")
   builder.add_conditional_edges("agent", tools_condition)  # route
   builder.add_edge("tools", "agent")         # loop back
   graph = builder.compile()
   graph.invoke({"messages": [HumanMessage("...")]})

   You see every step. You can insert any node anywhere in the loop.
   You can add conditional edges to break the loop on custom conditions.

GOOGLE ADK REACT LOOP (implicit, ADK runs it for you)

   agent = LlmAgent(
       model="bedrock/anthropic.claude-sonnet-4-5",
       tools=[get_weather, calculate],
       instruction="You are a helpful assistant.",
   )
   runner = Runner(agent=agent, session_service=InMemorySessionService())
   for event in runner.run(user_id="u1", session_id="s1", message=msg):
       if event.is_final_response():
           print(event.response.text)

   ADK runs the ReAct loop internally. You don't define nodes or edges.
   Advantage: less boilerplate. Disadvantage: less visibility and control.

LANGCHAIN ONLY (no loop — just a chain)

   chain = prompt | llm | StrOutputParser()
   result = chain.invoke({"question": "What is PTO?"})

   No loop. Single pass. For simple Q&A on fixed prompts this is enough.
   When you need iteration, tool calling, or branching: use LangGraph.


---
PART 7 — MULTI-AGENT: HOW EACH FRAMEWORK HANDLES IT
---

LANGGRAPH MULTI-AGENT

   Explicit graph with Send() for parallel dispatch.
   Each specialist is a subgraph (its own StateGraph, compiled).
   The supervisor graph adds specialist subgraphs as nodes.
   Aggregator node reads all results from the reducer list.

   Visibility: complete. Every specialist's every step is a traceable node.
   Flexibility: high. Any routing logic, any aggregation logic.
   Boilerplate: medium (you wire everything explicitly).

   supervisor -> [Send(hr_node), Send(payroll_node), Send(it_node)] -> aggregator

GOOGLE ADK MULTI-AGENT

   Use ParallelAgent or SequentialAgent to compose specialists.
   Each specialist is an LlmAgent with its own tools and instruction.
   ADK handles the dispatch and result collection internally.

   parallel_agent = ParallelAgent(
       sub_agents=[hr_agent, payroll_agent, it_agent]
   )

   Visibility: lower. You see inputs and outputs but not the internal dispatch.
   Flexibility: medium. You choose agent type but not the aggregation logic.
   Boilerplate: low (ADK wires the dispatch for you).

LANGCHAIN ONLY (parallel chains)

   RunnableParallel({
       "hr":      hr_chain,
       "payroll": payroll_chain,
       "it":      it_chain,
   }).invoke({"question": "..."})

   No agent loop. No tools. Pure parallel chain execution.
   Fine for parallel LLM calls, not for agents that need tools or memory.


---
PART 8 — STATE AND MEMORY: HOW EACH HANDLES IT
---

LANGGRAPH

   State = TypedDict. Explicit fields. You define every field.
   Reducer = Annotated[list, operator.add]. Controls how fields merge.
   Checkpointer = MemorySaver / SqliteSaver / PostgreSQL.
   thread_id = session key.
   get_state(config) = inspect state at any point.
   get_state_history(config) = all past states (time travel).

GOOGLE ADK

   Session = session.state dict (arbitrary key-value).
   SessionService = InMemorySessionService or VertexAI SessionService.
   user_id + session_id = identity.
   session.state["key"] = value (set from tools or agent callbacks).
   No equivalent of time travel or mid-graph state inspection.

LANGCHAIN

   ChatMessageHistory = list of messages in memory.
   RunnableWithMessageHistory = wraps a chain to inject/persist history.
   No graph state, no checkpointing, no reducers.
   Simple but not suited for multi-step agent state management.


---
PART 9 — OBSERVABILITY AND EVALUATION
---

LANGGRAPH + LANGCHAIN
   LangSmith: set LANGCHAIN_TRACING_V2=true.
   Automatic tracing of every node, LLM call, tool call.
   Dataset management, prompt versioning, evaluation pipelines.
   Human annotation UI.
   No built-in CLI eval (you write pytest or use LangSmith datasets).

GOOGLE ADK
   adk eval: built-in CLI evaluation against JSON test datasets.
   Metrics: tool_trajectory (right tools in right order), response_match.
   Cloud Logging + Cloud Trace for production observability on Vertex AI.
   No equivalent of LangSmith's dataset and prompt management.


---
PART 10 — WHEN TO USE WHICH
---

Use LANGCHAIN ONLY when:
   - You are building a RAG pipeline (no agent loop needed).
   - You are doing prompt engineering / template management.
   - You need a simple one-shot LLM call with structured output.
   - You want to swap LLM providers without changing code.
   Example: document Q&A, summarization pipeline, extraction chain.

Use LANGGRAPH when:
   - You need an agent loop with full visibility and control.
   - You need complex routing, branching, or retry logic.
   - You need parallel agent dispatch with custom aggregation.
   - You need human-in-the-loop (approval workflows).
   - You need time travel for debugging or audit.
   - You are on AWS, Azure, or a multi-cloud / cloud-agnostic stack.
   - Your team values explicit, testable, observable agent behavior.
   Example: multi-domain enterprise Q&A agent, healthcare triage,
   compliance workflow automation.

Use GOOGLE ADK when:
   - You are on GCP / Vertex AI and want native integration.
   - You want to deploy to Vertex AI Agent Engine with minimal config.
   - You want built-in evaluation (adk eval) out of the box.
   - You want A2A protocol for agent-to-agent communication.
   - You are prototyping quickly and want less boilerplate.
   - Your team prefers opinionated frameworks over flexible ones.
   Example: GCP-native customer service agent, Vertex AI pipeline,
   rapid prototype that becomes a Vertex AI deployment.

Use ALL THREE TOGETHER (possible, rare) when:
   - You need LangChain's retriever ecosystem (Bedrock KB, Pinecone, etc.)
   - but want ADK's evaluation harness and Vertex AI deployment
   - You can call LangChain retrievers as ADK tools (they are just functions).


---
PART 11 — INTERVIEW TALKING POINTS
---

"LangChain is the component layer — it gives you a uniform interface for LLMs,
tools, prompts, and retrievers across all providers. You can swap Bedrock for
OpenAI without touching your business logic. But LangChain alone has no agent loop,
no state, no branching, no persistence."

"LangGraph is the orchestration layer built on top of LangChain. It gives you an
explicit state machine for your agent: you define every node, every edge, every
routing decision. The loop is visible, testable, and traceable. The key primitives
are: State (the shared data bag), conditional edges (branching), Send() (parallel
dispatch), and checkpointing (persistence and human-in-the-loop)."

"Google ADK is an opinionated agent platform. It gives you built-in agent types
(LlmAgent, ParallelAgent, SequentialAgent), a session service, a runner, and a
built-in evaluation CLI. You write less boilerplate but you give up fine-grained
control over the loop. It is GCP-native and integrates directly with Vertex AI
Agent Engine for deployment."

"In multi_agent_aws_hc_solution_enhance we originally used ADK for orchestration
because it gave us parallel and sequential agent patterns quickly. We rewrote it
in LangGraph because our stack is AWS-native, and LangGraph gave us full visibility
into every routing decision, the Send() parallel dispatch pattern with operator.add
reducers for safe state accumulation, and the ability to add human-in-the-loop
checkpointing for compliance review workflows."

"The way I think about it: LangChain is your parts supplier, LangGraph is your
architect, and ADK is the general contractor who brings a pre-designed floor plan.
If you want maximum control and are on AWS, LangChain + LangGraph. If you want
fast delivery and are on GCP, ADK."
